Актуальная раскладка исходников — ``stages/``, ``scripts/``, ``docs/`` и корневой ``README.md``.
Ниже — старое описание языков (x86-примеры из live-bootstrap).

hex0
====
``hex0`` - достаточно тривиальный "язык", который может быть относительно просто проверен человеком, особенно с комментариями (строки, начинающиеся с ``#`` and ``;``):

.. code:: scheme

    # :loop_options [_start + 0x6F]
        39D3            ; cmp_ebx,edx                 # Check if we are done
        74 14           ; je !loop_options_done       # We are done
        83EB 02         ; sub_ebx, !2                 # --options
 
С помощью этого языка собираются и запускаются наши первые стадии. Для инициализации файлов системой каждый ``hex0`` файл должен начинаться со строки ``src <filename>.hex0`` и заканчиваться нулевым символом (благодаря отдельному shell-скрипту). `Пример. <https://github.com/DEMest/Team-Project/blob/feature/stage3/builder-mvp/payload.hex0>`_

boot
====
Единственная стадия в бинарном формате, где мы принимаем условность "доверия изначальному компилятору" из-за размерной минималистичности. Нужна исключительно чтобы собрать вторую стадию из ``hex0`` и сделать jump.

Написано `зимней школой 2025 <https://github.com/ylab-nsu/ws25-bootstrap/tree/main>`_, слегка видоизменена для подтверждения отклика.

simon
=====
Минимальное ядро, написанное нами. На данный момент может инициализировать в "файловой системе" последующие файлы-стадии ``hex0`` в загрузочном образе, компилировать их и исполнять, что, теоретически, должно уже хватать для сборки более сложных стадий. 

Поддерживает прерывания с обработкой системных вызовов и переключением контекста. 

hex1
====
Последняя программа на hex0, которую мы собираем. hex1 - это простое расширение hex0, добавляющее метки в виде одного символа и позволяющее вычислять 32-битные смещения от текущей позиции в коде до метки. Код на hex1 может выглядеть так:

.. code:: scheme

    :a #:loop_options
        39D3            ; cmp_ebx,edx                 # Check if we are done
        0F84 %b         ; je %loop_options_done       # We are done
        83EB 02         ; sub_rbx, !2                 # --options

hex2
====
hex2 - это наш последний шестнадцатеричный язык, который добавляет поддержку меток произвольной длины. Он также позволяет получать к ним доступ через 8/16/32-битные относительные адреса (!, @, %) и через 16/32-битные ($, &) абсолютные адреса:

.. code:: scheme

    :loop_options
        39D3                  ; cmp_ebx,edx                        # Check if we are done
        74 !loop_options_done ; je8 !loop_options_done             # We are done
        83EB 02               ; sub_ebx, !2                        # --options

M0
==
Макроассемблер M0 - это самый простой язык ассемблера, который можно создать, но который позволяет разрабатывать более сложные программы. Он включает в себя всего одно ключевое слово: DEFINE и использует языковые свойства hex2.

Таким образом, код M0 выглядит следующим образом:

.. code:: scheme

    DEFINE cmp_ebx,edx 39D3
    DEFINE je 0F84
    DEFINE sub_ebx, 81EB

    :loop_options
        cmp_ebx,edx                         # Check if we are done
        je %loop_options_done               # We are done
        sub_ebx, %2                         # --options

M1
==
M1 — тот же макроассемблер, что и M0, но исходник написан уже на M0, а не на hex2.
Опкоды и поля регистров задаются через ``DEFINE`` (как в ``riscv64_defs.M1``), дальше идут мнемоники, метки hex2 (``:`` ``$`` ``@`` ``!`` ``~`` ``%``) и строки ``"..."``.

Исходник: ``stages/03-m0/M1_riscv64.M0``. Собирается так::

    do M0.bin M1.M0 M1.hex2
    do hex2.bin M1.hex2 M1.bin

Дальше M1 собирает программы на M1::

    do M1.bin testE.M1 testE.hex2
    do hex2.bin testE.hex2 testE.bin
    do testE.bin

cc_riscv64?
===========
Следующая стадия после M1 — компилятор C (M2-Planet / cc_riscv64), который сам написан на M1.
В stage0-posix-riscv64 он есть как ``cc_riscv64.M1``; до него как раз нужна рабочая связка M0 → M1.
