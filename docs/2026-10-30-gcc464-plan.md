# GCC 4.6.4 под Tilck — поэтапный план

> **Исполнитель:** одна фаза целиком вместе с гейтом. Ревью по фазам нет, в конце один отчёт.
> **Коммиты** — только после явного «да» пользователя.
> **Всё проверяется на QEMU.**

**Цель:** под Tilck GCC 4.6.4 (форк Ekaitz с RISC-V, коммит `c0d20242b1d6668a0939c9ccf128d404dce9071e`) собран гостем. Сначала tcc, потом сам GCC, а `make bootstrap` подтверждает `Comparison successful`. Установленный gcc собирает и запускает программы на C и C++ с binutils 2.30 и musl.

**Путь** — как у Ekaitz и Andrius на riscv64 (посты Ekaitz 12–14, их `commencement.scm`):
1. tcc собирает GCC только для C с `--disable-bootstrap` → **gcc-1**;
2. gcc-1 пересобирает musl → **musl-2**. Без этого следующий GCC падает на `genmddeps`, так пишет Ekaitz;
3. gcc-1 и musl-2 запускают **`make bootstrap`** для C: stage1 (gcc-1) → stage2 → stage3 и сравнение stage2 ≡ stage3 → **gcc-3**;
4. gcc-3 собирает GCC с C и C++ → `cc1plus`, libstdc++.

**Архитектура:** ступени Tilck, как в планах 3–4 (`tilck.py --rung NAME`, `run.kaem` → `bash run.sh`, `rootfs.tar` по цепочке через `/dev/outbox`). Исходники — `build/sources/gcc-4.6.4-c0d20242.tar` (466 МБ, sha256 `fb8689273a59812638f7d38a6187ebd32fd0487c0a90100d12a86e6251bbbac0`, `git archive` без префикса). Архив кладётся в initrd как есть. Гость распаковывает только нужное и исключает `gcc/testsuite`, `libjava`, `gcc/ada`, `libgo`, `gcc/go`, `gcc/java`, `gcc/fortran`, `gcc/objc*`, `libstdc++-v3/testsuite`, `boehm-gc`, `libffi` и подобное. `gengtype-lex.c` (в git его нет) генерирует наш flex внутри `make`.

**Время:** под эмуляцией GCC собирается долго. Ступени запускаются в фоне с таймаутами в часах и с метками прогресса на каждую подсистему (`gcc-1 configured`, `libiberty built`, `cc1 built`, `libgcc built`, …). При падении в UART уходят хвосты логов (`tail -60`).

| Фаза | Ступень | Гейт |
|------|---------|------|
| 1 | `gcc1` | `xgcc -v` → `gcc version 4.6.4`; gcc-1 собирает и запускает `hello.c` с binutils + musl → `hello from gcc-1` |
| 2 | `musl2` | musl 1.1.24 собран gcc-1 своим `configure`/`make`; `hello` и `musl-proc` на musl-2 → `musl2 ok` |
| 3 | `gcc3` | `make bootstrap` (C) печатает `Comparison successful`; установленный gcc → `hello from gcc 4.6.4` |
| 4 | `gcc4` | GCC с `--enable-languages=c,c++`; `hello.cpp` с `iostream` → `hello from g++ 4.6.4`; `gcc -v` с `4.6.4` |

## Фаза 1: gcc-1 (собирает tcc)

**Вход:** ступень `gmp` (план 4, фаза 4) зелёная: `rootfs-gmp.tar` с gmp/mpfr/mpc, binutils и всеми утилитами.

### Задача 1. Подготовка исходников
- Распаковка с исключениями в `/build/gcc-src`. Список исключений — в README.
- **Патч Ekaitz** `tree-ssa-operands.c` / `ssa_operand_alloc` (пост 14: индекс через промежуточную переменную — обход ошибки tcc). Файл `19-gcc464/gcc1/patches/ssa-operand-alloc.patch`, применяется `patch -p1`. В README — ссылка и объяснение. Если по ходу удастся найти и исправить саму ошибку tcc (тест сначала, override стадии 11), патч можно снять, но это необязательно.
- Другие патчи — только по ошибке на госте, по одному, с README.

### Задача 2. configure и make
```
mkdir /build/gcc1 && cd /build/gcc1
/build/gcc-src/configure --prefix=/usr/gcc1 \
  --build=riscv64-unknown-linux-musl --host=riscv64-unknown-linux-musl --target=riscv64-unknown-linux-musl \
  --enable-languages=c --disable-bootstrap --disable-multilib --disable-nls --disable-shared \
  --disable-libmudflap --disable-libssp --disable-libgomp --disable-libquadmath --disable-lto \
  --disable-decimal-float --disable-threads --disable-libstdcxx-pch \
  --with-gmp=/usr --with-mpfr=/usr --with-mpc=/usr \
  --with-arch=rv64gc --with-abi=lp64d \
  --with-native-system-header-dir=/usr/include
make MAKEINFO=true && make install MAKEINFO=true
```
Окружение: `CC=tcc`, `CFLAGS=-g0` (tcc игнорирует `-O`), `LDFLAGS="-static -Wc,-static"`, `AR=ar`, `RANLIB=ranlib`, `CONFIG_SHELL=/bin/sh`. Если `--with-arch`/`--with-abi` у этой версии называются иначе, взять, как в `gcc/config.gcc` форка, и записать. Динамический загрузчик musl не нужен: все программы статические. `gcc` по умолчанию линкует статически (`-static` в specs или в тестах). Решение — в README.

### Задача 3. Тесты и гейт
- `/usr/gcc1/bin/gcc -v` → `gcc version 4.6.4`.
- `gcc -static hello.c -o hello && ./hello` → `hello from gcc-1`.
- `gcc -O2 -static` на маленьком тесте с `long long`, `double`, `switch`, рекурсией, `struct` по значению → `gcc1 sanity ok`.
- `tilck.py --rung gcc1` (из `rootfs-gmp.tar`): метки выше, `rootfs sha256 match`, `rung done gcc1`. Время каждой подсистемы — в отчёт.

## Фаза 3: `make bootstrap` (C)

### Задача 5
- `configure` как в задаче 2, но `--prefix=/usr`, без `--disable-bootstrap`, `CC=/usr/gcc1/bin/gcc`. Чтобы под эмуляцией было быстрее: `BOOT_CFLAGS="-O1 -g0"`, `STAGE1_CFLAGS="-O1 -g0"`. Значения — в README.
- `make bootstrap MAKEINFO=true` → в логе `Comparison successful`. Метка `bootstrap compare ok` ставится, только если строка есть и `make` вернул 0.
- `make install`; `/usr/gcc1` удалить из `rootfs`.
- Тесты: `gcc -v` → `4.6.4`; hello → `hello from gcc 4.6.4`; тест из задачи 3 → `gcc3 sanity ok`.
- `tilck.py --rung gcc3` (из `rootfs-musl2.tar`): метки, `rootfs sha256 match`, `rung done gcc3`.

## Фаза 4: C++

### Задача 6
