# GCC 9.5 под Tilck — поэтапный план

> **Исполнитель:** одна фаза целиком вместе с гейтом. Ревью по фазам нет, в конце один отчёт.
> **Коммиты** — только после явного «да» пользователя.
> **Всё проверяется на QEMU.** Готовых бинарей нет: только то, что собрал гость из закреплённых исходников.

**Цель:** под Tilck апстримный GCC 9.5.0 (C и C++) собран гостем. Сначала GCC 4.6.4 (ступень `gcc4`), потом сам GCC 9.5 через `make bootstrap` с `Comparison successful`. Установленный gcc 9.5 собирает и запускает программы на C и C++ с binutils 2.30 и musl 1.1.24.

**Путь:**
1. gcc 4.6.4 пересобирает gmp/mpfr/mpc версий, которые закреплены в GCC 9.5 (`contrib/download_prerequisites`). Заодно `make check` этих библиотек проверяет кодогенерацию 4.6.4 на тяжёлом числовом коде, до долгой сборки GCC.
2. g++ 4.6.4 собирает GCC 9.5 для C и C++ с `--disable-bootstrap` → **gcc9a**. Это промежуточная точка с образом: если 4.6.4 что-то соберёт криво, это видно через несколько часов, а не через сутки.
3. gcc9a запускает **`make bootstrap`** для C и C++: stage1 (собран gcc9a) → stage2 → stage3, затем сравнение stage2 ≡ stage3 → **gcc9**. После этого проверка неподвижной точки: cc1/cc1plus от gcc9a и от gcc9 компилируют одни и те же исходники GCC и должны выдать одинаковый результат (так в 4.6.4 нашлась ошибка `riscv_rtx_costs`).

Так же GCC 10.5 собирают в live-bootstrap `b1ceced7` (из GCC 4.7.4, `steps/gcc-10.5.0`). Отличия от них:
- сгенерированные файлы из тарболла принимаем как исходник, как и для 4.6.4: autogen, autoreconf, gperf, bison и flex не перезапускаем;
- binutils остаются 2.30, а не 2.41;
- musl остаётся 1.1.24, а не 1.2.5;
- у них одна стадия, у нас `make bootstrap`.

## Что известно заранее

- **Формат архива GCC 9.5 — PAX.** Перед каждым файлом стоит заголовок `x` с `atime`/`ctime`; у 102 путей длина больше 100 символов. tar 1.12 не знает PAX: он запишет заголовки как файлы `PaxHeaders.*` и обрежет длинные пути. Поэтому нужен свой распаковщик `paxx.c` (развитие `19-gcc464/gcc4/src/ustar-x.c`):
  - понимает `x`/`g` (`path`, `linkpath`, `size`), ustar `prefix`, обычные файлы, каталоги и симлинки;
  - читает из stdin, вход — `gzip -dc` (gzip 1.2.4);
  - берёт список исключений;
  - собирается gcc 4.6.4.

  Вне исключённых каталогов длинные пути есть только у 7 заголовков `libstdc++-v3/include/ext/pb_ds/detail/`. Архивы gmp, mpfr и mpc — обычный ustar без длинных путей, их распаковывает tar 1.12.
- **RISC-V и musl** GCC 9.5 поддерживает сам (`gcc/config/riscv/linux.h`, `MUSL_DYNAMIC_LINKER`). `libgcc/config/riscv/linux-unwind.h` берёт `ucontext_t` из `<sys/ucontext.h>`, так что патч `riscv-ucontext` от 4.6.4 не нужен. `--with-native-system-header-dir` есть в configure, патч `native-system-header-dir` тоже не нужен.
- **binutils 2.30.** Директиву `.attribute` (binutils 2.32) GCC 9.5 проверяет при configure (`gcc_cv_as_riscv_attribute`) и без неё не выдаёт.
- **awk.** GCC советует gawk ≥ 3.1.5, но live-bootstrap собирает GCC 10.5 нашим же gawk 3.0.4: gawk 5.3 у них появляется только после gcc-10.5.0.
- **perl** нужен libstdc++ только для версий символов. Берём `--disable-symvers`: у нас всё статическое.
- **Минимальные версии** у GCC 9.5 — gmp 4.3.2, mpfr 2.4.2, mpc 0.8.1, C++98 (g++ 4.6.4 подходит), make ≥ 3.80 (у нас 3.82), bash.
- **Объём исходников:** распакованный архив — 789 МБ. Без `gcc/testsuite` (285 МБ), Ada, Go, D, Fortran, Objective-C, BRIG, `libsanitizer`, `libstdc++-v3/testsuite` и подобного остаётся около 300 МБ.

## Время

Оценка грубая. Ступень `gcc4` 4.6.4 (C и C++, одна стадия) шла около 1,7 часа, `make bootstrap` 4.6.4 только для C — около 3,5 часа. У GCC 9.5 исходников в 2–3 раза больше, и всё компилируется как C++.

| Ступень | Оценка |
|---|---|
| `gmp9` | ~1,5 ч (из них `make check` больше половины) |
| `gcc9a` | 5–8 ч |
| `gcc9` | 15–25 ч (три стадии с C++) |

Поэтому:
- на время долгих ступеней мак не засыпает: запросить keep-awake у приложения;
- таймаут ступени `gcc9` — 72 ч;
- метки прогресса на каждую подсистему;
- при перезагрузке ступень перезапускается со своего входного образа, а не с нуля.

## Фаза 1: `gmp9` (gcc 4.6.4 собирает библиотеки для GCC 9.5)

### Задача 1. Распаковщик PAX
- `src/stages/20-gcc95/src/paxx.c`, примерно 300 строк C, без зависимостей кроме libc.
- Использование: `gzip -dc ARCHIVE | paxx -C DIR -X EXCLUDES`. Поддерживает:
  - заголовки PAX `x` (на один файл) и `g` (глобальные) с ключами `path`, `linkpath`, `size`;
  - ustar `prefix`;
  - типы `0`/`\0`, `5`, `2`, `1` (жёсткая ссылка — копия);
  - режим доступа.

  Другие типы — ошибка с именем файла. В конце печатает `paxx: N files, D dirs, L links, P pax headers`.
- Тест на госте, в этой же ступени: маленький PAX-архив с путём длиннее 100 символов (собирается из исходника теста, без хостовых архивов), распаковка, сверка содержимого → `paxx ok`. Потом пробная распаковка `gcc-9.5.0.tar.gz` с исключениями: число файлов и 7 заголовков `pb_ds` на месте → `paxx gcc ok`.

### Задача 2. gmp, mpfr, mpc
- По образцу стадии 18, но `CC=gcc` (4.6.4), `CFLAGS="-O2 -g0"`, статически, `--prefix=/usr` (поверх 4.3.2/2.4.2/0.8.1), `--disable-shared`.
- gmp 6.1.0: `--disable-assembly` и `--host=riscv64-unknown-linux-musl` (gmp 6.1 знает riscv64 в `configfsf.sub`). Если `configfsf.guess` не узнаёт хост, `--build` задаётся явно.
- `make check` каждой → `gmp check ok`, `mpfr check ok`, `mpc check ok`. Падение теста — это повод искать ошибку в 4.6.4 или в Tilck, а не выключать тест.
- Старые `.a` и заголовки 4.3.2/2.4.2/0.8.1 удалить перед установкой, чтобы не смешались.
- `tilck.py --rung gmp9`: `gmp9 ok`, `rootfs sha256 match`, `rung done gmp9`.

## Фаза 2: `gcc9a` (g++ 4.6.4 собирает GCC 9.5)

### Задача 3. Исходники
- `gcc-9.5.0.tar.gz` в initrd. В госте `gzip -dc | paxx` в `/build/gcc-src` с исключениями `20-gcc95/gcc9a/excludes`. Нужные файлы (как `testsuite/Makefile.in` у libstdc++ в 4.6.4) не исключать: проверить по первой ошибке configure и записать в README.
- Исключения: `gcc/testsuite`, `libgo`, `gcc/go`, `gotools`, `libphobos`, `gcc/d`, `gcc/ada`, `libada`, `gnattools`, `gcc/fortran`, `libgfortran`, `gcc/objc`, `gcc/objcp`, `libobjc`, `gcc/brig`, `libbrig`, `libhsail-rt`, `libsanitizer`, `libvtv`, `liboffloadmic`, `libgomp`, `libitm`, `libquadmath`, `libstdc++-v3/testsuite/*` (кроме `Makefile.in`), `*.gmo`, `*.info`.
- Патчи — только по ошибке на госте, по одному, каждый с объяснением в README.

### Задача 4. configure и make
```
mkdir /build/gcc9a && cd /build/gcc9a
/build/gcc-src/configure --prefix=/usr/gcc9a \
  --build=riscv64-unknown-linux-musl --host=riscv64-unknown-linux-musl --target=riscv64-unknown-linux-musl \
  --enable-languages=c,c++ --disable-bootstrap --disable-multilib --disable-nls \
  --disable-shared --enable-static --disable-lto --without-isl \
  --disable-libsanitizer --disable-libssp --disable-libgomp --disable-libitm \
  --disable-libquadmath --disable-libvtv --disable-symvers --disable-libstdcxx-pch \
  --enable-threads=posix --disable-sjlj-exceptions \
  --with-gmp=/usr --with-mpfr=/usr --with-mpc=/usr \
  --with-arch=rv64gc --with-abi=lp64d \
  --with-native-system-header-dir=/usr/include
make MAKEINFO=true && make install MAKEINFO=true
```
- Окружение: `CC=gcc`, `CXX=g++` (4.6.4), `CFLAGS=CXXFLAGS="-O2 -g0"`, `LDFLAGS=-static`, `CONFIG_SHELL=/bin/sh`.
- Метки: `gcc9a configured`, `gcc9a support built` (libiberty, libcpp, libdecnumber, zlib), `cc1 built`, `cc1plus built`, `xgcc built`, `libgcc built`, `libstdc++ built`, `gcc9a installed`.
- Установка `make install` по частям, если понадобится, как в 4.6.4 (`install-headers-cp`).

### Задача 5. Тесты и гейт
- `/usr/gcc9a/bin/gcc -v` → `gcc version 9.5.0`.
- `hello.c` → `hello from gcc 9.5`; `hello.cpp` (iostream, string, vector, исключения) → `hello from g++ 9.5`.
- `sanity.c` (тест 4.6.4 плюс C11: `_Static_assert`, `_Generic`, анонимные struct/union) и `sanity.cpp` (C++14: `auto`, лямбды, `std::unique_ptr`, `std::map`, range-for, `constexpr`, `std::sort` с компаратором) на `-O2` → `gcc9a sanity ok`.
- `tilck.py --rung gcc9a` (из `rootfs-gmp9.tar`): метки, `rootfs sha256 match`, `rung done gcc9a`. Время каждой подсистемы — в отчёт.

## Фаза 3: `make bootstrap` (C и C++)

### Задача 6. bootstrap
- configure как в задаче 4, но `--prefix=/usr`, без `--disable-bootstrap`; плюс `--with-boot-ldflags=-static` и `--with-stage1-ldflags=-static`. `CC=/usr/gcc9a/bin/gcc`, `CXX=/usr/gcc9a/bin/g++`.
- Флаги: `STAGE1_CFLAGS="-O1 -g0"`, `BOOT_CFLAGS="-O2 -g0"` (`-g0` экономит память и время; проверка stage2 ≡ stage3 от этого не слабее). Значения — в README.
- `make bootstrap MAKEINFO=true`. Метки: `stageN cc1 built`, `stageN cc1plus built`, `stageN libstdc++ built`. Если ступень упрётся в память гостя — `bootstrap-lean`, с записью в README.
- `bootstrap compare ok` ставится, только если в логе есть `Comparison successful` и `make` вернул 0.
- Пересчёт сравнения (как `19-gcc464/gcc3/run.sh`, коды `cmp` раздельно). Здесь же закрыть вопрос 4.6.4 «465 differ»: для двух-трёх пар напечатать, какие файлы сравнивает `compare` GCC и какие наш пересчёт (пути, размеры, `cmp -l | head`). Найти, где пересчёт расходится с `compare`, и записать ответ в README обеих стадий.

### Задача 7. Установка и неподвижная точка
- `make install`. `cc1`/`cc1plus` от gcc9a скопировать в `/build/fp/a/` до удаления `/usr/gcc9a`.
- Неподвижная точка, как в `19-gcc464/gcc4/run.sh`: cc1 и cc1plus от gcc9a и от gcc9 компилируют одни и те же исходники с одним драйвером и одинаковыми флагами (`ALL_CPPFLAGS` собранного `gcc/`). Источники:
  - не меньше 40 файлов `gcc/*.c` (в 9.5 это C++) на `-O1` и часть из них на `-O2`;
  - несколько файлов libstdc++ и `libgcc2.c`.

  Одинаковый `.s` — «same». Итог `fixedpoint N files, 0 differ` → `fixedpoint ok`. Тест раскладки `cc1 layout ok` из 4.6.4 не нужен: в 9.5 нет ошибки `riscv_rtx_costs`. Если проверка что-то найдёт, тест добавляется по находке.
- Тесты от `/usr/bin/gcc`: `gcc -v` → `9.5.0`, `hello from gcc 9.5.0`, `hello from g++ 9.5.0`, `gcc9 sanity ok` (тесты задачи 5).
- `/usr/gcc9a` удалить; `/usr/bin/gcc` — это 9.5. Есть ли 4.6.4 в образе, записать: `make install` 9.5 перезаписывает `gcc`/`g++`, а каталоги `lib/gcc/.../4.6.4` и `libexec/gcc/.../4.6.4` можно удалить.
- `tilck.py --rung gcc9` (из `rootfs-gcc9a.tar`, таймаут 72 ч): метки, `rootfs sha256 match`, `rung done gcc9`.

### Задача 8. Документы
- README `20-gcc95`: ступени, исключения, флаги, патчи с причинами, время каждой стадии, размеры, ответ на «465 differ».
- Журнал в `docs/2026-10-28-gcc464-ladder-design.md`, статус в `docs/bootstrap-to-linux.md` (строка 4 — готово), записка о паузе.

## Риски и что делать

| Риск | Признак | Действие |
|---|---|---|
| g++ 4.6.4 (форк) неправильно компилирует GCC 9.5 | падение `make check` в `gmp9`, ICE или неверный результат gcc9a, `Comparison` или `fixedpoint` не сходятся | как в 4.6.4: свести к маленькому тесту, найти причину в форке, патч с тестом, перегнать затронутые ступени |
| Ошибка Tilck (память, mmap, процессы) на больших cc1plus | падения, зависания, разный результат при повторе | тест ядра, исправление в `12-tilck`, проверка, что прежние образы не меняются |
| binutils 2.30 слишком старые для 9.5 | ошибки `as`/`ld` в libgcc или libstdc++ | ступень с более новыми binutils (2.35 или 2.41, сборка gcc 4.6.4) перед `gcc9a` — отдельно спросить пользователя |
| Не хватает памяти гостя (8 ГБ) | `out of memory` в stage2/3 | `-g0` уже включён; `bootstrap-lean`; убрать лишние каталоги после стадий |
| Перезагрузка мака | QEMU пропал | перезапуск ступени с её входного образа; keep-awake на время прогона |
