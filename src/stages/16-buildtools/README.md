# 16 — build tools on Tilck (rung `build1`)

Rung `build1` of the Tilck ladder (14-seed README, "Rungs on Tilck"): starting from `15-early-tools/artifacts/rootfs-tools2.tar` (bash 2.05b, coreutils 5.0, make 3.82, sed, tar, gzip, bzip2, patch, yacc, tcc-m3 on musl), Tilck builds the tools a `configure` script needs: grep 2.4, gawk 3.0.4, diffutils 2.7, m4 1.4.7, flex 2.6.4 (live-bootstrap's `mk/` Makefiles), the coreutils 5.0 programs rung tools2 did not build, and findutils 4.2.33 with its own `./configure`. Then it runs a real `./configure && make && make install` of a fresh grep 2.4 and the installed grep, and hands `/usr` back as `artifacts/rootfs-build1.tar`, the rootfs of rung `binutils`.

```bash
python3 -u src/scripts/tilck.py --rung build1
```

`RUNGS["build1"]` (`src/scripts/tilck.py`): rootfs `15-early-tools/artifacts/rootfs-tools2.tar`, steps `steps/` (`run.kaem` is the one line `/bin/sh /initrd/steps/run.sh`: from this rung on the work is a bash script), the seven tarballs below, timeout 7200 s.

## `steps/run.sh`

1. `export SHELL=/bin/sh CONFIG_SHELL=/bin/sh LDFLAGS=-static TARGET=riscv64-unknown-linux-musl` (`/bin/sh` is rung-init's link to bash; tcc-m writes a dynamic executable without `-static`, which Tilck refuses to run), `cp -R /initrd/steps/. /steps/`.
2. live-bootstrap's `build()` (`steps/helpers.sh` at the pin), cut down to what these recipes use: in `/steps/PKG` the sources check, `rm -rf build; mkdir build; cd build`, `. pass1.sh` if the recipe has one, then `src_unpack`, `cd` into the unpacked directory, `src_prepare`, `src_configure`, `src_compile`, `src_install`, each the recipe's function or the default (`call`, `default` as in `helpers.sh`); then `rm -rf build`. Defaults as `helpers.sh`: unpack the first `sources` line (`gzip -dc`/`bzip2 -dc` into `tar xf -`), apply `patches/*.patch` with `patch -d.. -Np0`, copy `mk/main.mk` to `Makefile`; `make -j1 -f Makefile PREFIX=/usr`; `make -f Makefile install PREFIX=/usr DESTDIR=`. Not taken over: download, preseed, the `DESTDIR` fakeroot and package step (we install straight into `/usr`), strip/postprocess, checksums of the results.
3. Order: grep, gawk, diffutils, m4, flex, coreutils-extra, findutils (the plan's list, with the extra coreutils programs before the first `configure`; live-bootstrap's manifest has grep, m4, flex, diffutils, coreutils pass 2, gawk, …, findutils).
4. Version lines (`grep --version` … `uname --version`, the marks), `tests/tools-test.sh` in `/build/t`, `tests/configure-test.sh` in `/build/cfgtest`.
5. `/usr` packed as in rung tools2: `filelist`, `mkustar`, `catm /dev/outbox`, `sha256sum -o`, `echo "rootfs sha256 HEX"` (bash's `read`/`echo` replace tools2's `sha256-prefix` file), `rung done build1`.

## Recipes (`steps/<pkg>/`)

Copies of live-bootstrap's `steps/<pkg>/` (`sources`, `mk/main.mk`, `pass1.sh`); `diff -r` against the pin shows exactly the changes below.

**Generated files from the release tarballs** (policy of this plan, design doc): kept — flex's `src/scan.c`, `src/parse.c`, `src/parse.h`, `src/skel.c` (live-bootstrap deletes them and regenerates with flex 2.5.11 and heirloom yacc, which we do not have yet); coreutils' `lib/getdate.c` (bison output; `getdate.y` needs bison's `%pure_parser`, our oyacc stops with "syntax error"); findutils' `configure`, `Makefile.in`s, its gnulib copy, `doc/find.info` and `po/*.gmo` (no autoreconf, no gnulib import, `MAKEINFO=true`); grep 2.4's `configure` (the configure test). Regenerated by our yacc: gawk's `awktab.c` (live-bootstrap's `pass1.sh` deletes it; `mk/main.mk` makes it with `yacc awk.y` instead of `bison`; oyacc reports 62 shift/reduce conflicts, as byacc does for this grammar). grep, diffutils and m4 have no parser sources.

- **all**: every link line gets `-static` (`LDFLAGS = -static` in `mk/main.mk` and `$(LDFLAGS)` where a link line had none: gawk, flex; m4's `LDFLAGS = -L . -lm4` → `-static -L . -lm4`).
- `grep-2.4`, `mk/main.mk`: `CFLAGS` + `-DSTDC_HEADERS=1 -DHAVE_STRING_H=1 -DHAVE_STDLIB_H=1` (without them `strerror` is implicit `int`, its pointer cut to 32 bits). `egrep` and `fgrep` are built as upstream's `src/Makefile.am` builds them (the common objects with `egrepmat.o` / `fgrepmat.o`) instead of live-bootstrap's `ln -sf grep egrep`: grep 2.4 takes its matcher from those objects, not from `argv[0]`, so the links were a second plain grep (`egrep -c 'an|err'` gave 0), and autoconf 2.13's `AC_EGREP_CPP` then decided that `size_t` does not exist (`#define size_t unsigned` in grep's own `confdefs.h`).
- `gawk-3.0.4`: `mk/main.mk` `bison $^ -o $@` → `yacc $^` + `mv y.tab.c $@`; new `patches/alloca-size_t.patch` (`awk.h` declares `alloca (unsigned)` for `-DC_ALLOCA`, musl's `stdlib.h` → `alloca.h` has `alloca (size_t)`: tcc "incompatible types for redefinition"). `pass1.sh` unchanged (it deletes `awktab.c` and `pc/config.h`).
- `diffutils-2.7`, `mk/main.mk`: `CFLAGS` + `-DSTDC_HEADERS=1 -DHAVE_STRING_H=1 -DHAVE_STDLIB_H=1 -DHAVE_UNISTD_H=1 -DHAVE_TIME_H=1 -DHAVE_FCNTL_H=1 -DHAVE_SYS_WAIT_H=1 -DHAVE_LIMITS_H=1` (implicit `ctime` cut the `diff -c`/`-u` header's pointer, implicit `lseek` returned an `int`).
- `m4-1.4.7`: only `-static`.
- `flex-2.6.4`: `pass1.sh` without `rm src/parse.c src/parse.h src/scan.c src/skel.c`; `mk/main.mk` without the rules that regenerate them (`flex-tmp`, `scan-tmp.c`, `scan.c`, `parse.c parse.h`, `skel.c`: `scan.c: scan.l flex-tmp` would rebuild `scan.c` with a `flex` we do not have) and without `-lm` (the sysroot has no `libm.a`; musl's math is in `libc.a`, and its `make install` would add empty `libm.a` — rung `binutils`/`gmp` may want one for `-lm`).
- `coreutils-extra` (new, from live-bootstrap's `coreutils-5.0/pass2.sh` + `mk/pass2.mk`): `sources` = coreutils 5.0's; `mk/main.mk` = rung tools2's `mk/main.mk` (with its musl changes) with `COREUTILS = uname env date dd du nice` and a `chown` target (`chown.o chown-core.o`), `lib/getdate.o` in `LIB_SRC` (for `date`), `-DHOST_OPERATING_SYSTEM=\"Linux\"` (from `pass2.mk`; `uname -o`), and for `lib/ftw.o` (`du`) the two macros configure's `m4/dos.m4` puts in `config.h` (`FILESYSTEM_PREFIX_LEN(f)=0`, `ISSLASH(c)=((c)=='/')`); `install` installs only these 7. Of the plan's list, `sleep`, `printf`, `basename`, `dirname`, `pwd`, `true`, `false`, `ln`, `touch`, `rmdir` are already in rung tools2, `cmp` comes from diffutils, and coreutils 5.0 has no `mktemp` (added in coreutils 7.1; configure scripts fall back without it). `pass1.sh`: `pass2.sh`'s `src_prepare` (copy `fnmatch_.h`, `ftw_.h`, `search_.h`, `touch config.h`) without its deletions of generated files. `patches/`: of tools2's, the five that change `lib/` (`modechange`, `mbstate`, `sort-locale`, `tac-uint64`, `musl-getline`), and new `ftw-enosys-chdir.patch`: when `fchdir()` fails with `ENOSYS` (Tilck has none) `lib/ftw.c` falls back to `chdir()` of the whole path from the start while the cwd is already the parent (`du` of nested directories: "cannot change to directory"); the patch uses the last component.
- `findutils-4.2.33`: `sources` without the gnulib line, no `import-gnulib.sh`, no `force-getcwd-fallback.patch` (it patches `gnulib/m4/`, used only by `autoreconf`); `pass1.sh` without `src_prepare` (gnulib import, `autoreconf`, `rm doc/find.info po/*.gmo`); `src_configure` keeps live-bootstrap's `CC=tcc`, `--host="${TARGET/-musl/-gnu}"` and `CPPFLAGS=-D__UCLIBC__` (gnulib's `freadahead.c` has no musl branch; with `__UCLIBC__` and no `__STDIO_BUFFERS` it returns 0) and adds `--build` (the same: `config.guess` cannot guess Tilck, whose `uname -s` is `Tilck`; 2007's `config.sub` accepts any `CPU-unknown-OS`), `LD=tcc` (gettext's `AC_LIB_PROG_LD` stops with "no acceptable ld found in $PATH"; there is no `ld` before binutils) and `gl_cv_func_getcwd_path_max=yes` (the configure probe fails on Tilck, and gnulib's replacement `getcwd` walks `..` with `openat`/`fstatat` on real directory fds, which Tilck does not implement: `find: cannot get current directory`; musl's `getcwd` is the system call); `make` and `make install` with `AR="tcc -ar"` (the Makefiles say `AR = ar`; there is no `ar` before binutils; `RANLIB` is `:`, configure finds none). New `patches/tilck-nofollow.patch`: find's `check_nofollow()` says no for `uname -s` `Tilck`, so find enters directories with `chdir()` + `lstat()` instead of `open(O_NOFOLLOW)` + `fchdir()` (`ENOSYS`; with gnulib's fchdir emulation, `ac_cv_func_fchdir=no`, `find/defs.h` turns `fchdir` into `(-1)`).

## Fixed elsewhere (found by this rung)

- tcc: `lr`/`sc` were encoded as AMOAND/AMOMINU, so every musl atomic zeroed its word and musl's `malloc` never reused a free chunk; bash ran out of memory in findutils' `configure` (11-tcc7 README, test `atomicn.c`). The seed, Tilck, musl and rungs tcc, tools1, tools2 were rebuilt (new sha256s in the 14-seed and 15-early-tools READMEs).
- rung-init reaps orphans (14-seed README): unreaped zombies kept their cwd, and `rm -rf` of findutils' build tree failed with `Resource busy`.
- Tilck `brk` hands out zeroed pages (12-tilck README, `brkzero ok`): gawk read a node field it never set and crashed when stdin was a pipe.
- Tilck `getpriority`/`setpriority` (12-tilck README, `prio ok`): `nice: cannot get priority: Function not implemented`.
- Tilck released no exec lock after trying a `#!` script as ELF (12-tilck README, `scriptlock ok`): after `rm` of an executed script (findutils' `configure`), a new file at the same inode address could not be written (`tcc: error: could not write 'getopt.o: Text file busy'` in the configure test of the second gate run).
- Tilck panicked when a timer tick arrived during the previous one (12-tilck README): about one rung tools2 in four after the tcc fix; the upstream check tolerates only x86's timer number.

## Known gaps (for the next rungs)

- Tilck has no `fchdir` and no `*at()` with a real directory fd (`ENOSYS`); worked around above for find and du.
- Fixed in plan 4 phase 3 (12-tilck README, `sharedoff ok`): a forked child did not share the file offset of the parent's open files (Tilck duplicated each handle with its own position): `(/usr/bin/echo aaaa; /usr/bin/echo bb) > f` leaves `bb` + the rest of `aaaa`'s line, and in a `configure` everything the children write to `config.log` through fd 5 lands at their own offsets (grep 2.4's `config.log` is 155 lines of fragments). Output files made by one process (`cat > f`, `sed … > f`, `>>`) are right. Builds that write one file from several processes (`make > log 2>&1`, `(a; b) > f`) need this fixed in Tilck.
- Fixed in plan 4 phase 3 (12-tilck README, `abort ok`): musl's `abort()` in a signal handler (gawk's SIGSEGV handler) hung the process: Tilck delivered nothing while a handler ran, and the last `a_crash()` faulted forever.
